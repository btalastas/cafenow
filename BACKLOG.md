# CafeNow backlog index

The [MVP feature tasks and processes](docs/planning/MVP-FEATURE-TASKS-AND-PROCESSES.md) contains the 47 task definitions and acceptance outputs. The shared ServiceNow MVP VTB holds current owners, dates, progress and evidence. This index establishes pickup order without duplicating live status.

## Starting sequence

| Stage | Task IDs | Expected output |
| --- | --- | --- |
| Scope/delivery | P01 | Governing source, MVP boundaries, deadline, capacity and checklist decisions |
| Process/platform | P02, P03 | Business rules/diagrams and feasible environment/architecture |
| Five foundation cards | D01, S01, U01, T01, X01 | Dictionary/relationships, access matrix, employee sketches, test cases and scheduled/import clarification |
| Data and identities | D02–D04, S02, then D05 | Configured data model, personas and repeatable seed data |
| First integrated slice | S03–S04, B01–B03, U02, V02; C01–C03 if selected | Validated employee order and vendor visibility/action with access tests |
| Complete behavior | U03, V01, V03, B04–B05, N01–N02, F01–F03 | Tracking, menu maintenance, batches, cancellation/delays and notices |
| Reporting/checklist | A01–A02, X02 and I01–I02 if required | Reconciled reports and approved scheduled/import demonstrations |
| Verify and hand off | T02–T10 alongside feature delivery | Test/defect evidence, usable interfaces and repeatable demo |

P01–P03 are reported on the VTB. The five foundation card texts were prepared in chat; their creation/completion is not verified. Refer to exact task dependencies before pickup. X01 can reuse decisions already captured during P01/P03.

## Board use

See [WEEK-ONE-BOARD.md](docs/planning/WEEK-ONE-BOARD.md) for the starting eight cards, labels, lanes, card template and W01–W12 mapping. Select a realistic Week 1 subset after agreeing capacity. Add one card per detailed task ID; split large work into linked subtasks if needed rather than duplicate work-package cards.

Scope changes belong in [DECISIONS.md](DECISIONS.md), followed by updates to affected requirements and task definitions. Deferred product scope is listed in [PROJECT.md](PROJECT.md).
